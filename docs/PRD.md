# 广告自主浏览与智能分类平台 · MVP 产品需求文档（简版）

| 项目信息 | 内容 |
| --- | --- |
| 产品名称 | 广告发现站（内部代号：`ad_discovery_platform`） |
| 版本 / 日期 | PRD V1.0 / 2026-10-27 |
| 文档语言 | 简体中文 |
| 技术栈（已定，不可变更） | 前端 React + Vite（单页应用）；后端 FastAPI + SQLAlchemy + SQLite（与前端同源托管）；响应式 Web |
| 定位一句话 | 把被动打断用户的广告，变成用户**自主发现、筛选、管理**的商业信息 |
| 形态边界 | 一人公司 MVP，响应式 Web，无原生 App |
| 上游依据 | 《广告自主浏览与智能分类平台_一人公司项目计划书_V1.0》 |

**原始需求复述**：做一个广告可以被用户"主动逛"的网站。用户不需要注册就能按类别浏览、搜索、筛选广告，看到卡片上的广告标识、商家和有效期，能收藏/隐藏/举报/设置偏好；商家填表提交广告，提交后处于待审核、未经审核不公开；运营者登录后台审核通过/拒绝/下架/编辑并记录原因；系统按统一口径记录展示、详情、点击、收藏、举报事件，给商家一份简单效果报告。全程显著标注广告、不用暗黑模式、外链先提示离开平台。

## 1. 产品目标与非目标

### 1.1 目标（3 个，正交）

| # | 目标 | 可衡量判据（MVP 试点期） |
| --- | --- | --- |
| G1 | **验证"用户愿意主动逛广告"**：让有明确需求的用户在不被打断的前提下，主动进入、按类别/关键词找到商业信息 | 试点访问中 ≥30% 产生至少一次搜索或筛选（主动浏览率）；≥25% 的列表访问进入详情页（详情查看率） |
| G2 | **建立可信度**：任何一条公开广告都能被用户一眼识别为广告，并知道是谁投的、到什么时候有效 | 100% 公开广告含"广告"标识 + 商家名 + 有效期；过期广告对用户可见率为 0；广告类投诉中"未标识/误认为普通内容"占比 <5% |
| G3 | **跑通一人可运营的供给闭环**：商家自助提交 → 人工审核 → 上线 → 出报告，单条广告运营耗时可控 | 单条广告审核平均耗时 ≤10 分钟；从提交到首次审核结论 ≤24h（工作日内）；≥1 家商家拿到报告后表达续投意愿 |

### 1.2 非目标（本版明确不做）

| # | 不做 | 说明 |
| --- | --- | --- |
| N1 | 原生 iOS/Android App | 仅响应式 Web |
| N2 | AI 推荐算法、用户画像、实时竞价/付费排名 | 排序不接受付费加权，避免"花钱就能插队" |
| N3 | 自动抓取全网广告 | 仅商家自主提交 + 人工录入 |
| N4 | 平台内交易、支付托管、物流、退款 | 只做出站跳转，不承接交易 |
| N5 | 社交动态、评论、聊天、直播、积分商城 | 无评论功能，反馈只走"举报/意见" |
| N6 | 跨站追踪、第三方像素、敏感画像 | 事件只在站内产生 |
| N7 | 医疗、金融、博彩、酒类、成人、政治类广告 | 分类体系不设这些类别，提交页显式拒收 |
| N8 | 多级分销/联盟佣金结算自动化 | 支付仅人工确认（P2） |

## 2. 三条核心用户旅程

### 旅程 A：匿名浏览发现（不注册）

| 步 | 用户动作 | 系统行为 | 对应页面 |
| --- | --- | --- | --- |
| A1 | 打开首页 | 首次访问下发匿名标识 Cookie；展示首屏说明"这里全是带广告标识的商家推广，按类别自己挑" | `/` |
| A2 | 点一个一级类别，或直接搜索关键词 | 跳分类列表 / 搜索结果；应用默认排序"最新发布" | `/c/:slug`、`/search` |
| A3 | 浏览卡片（含广告角标、商家、价格、有效期、地区） | 卡片进入视口 ≥50% 且停留 ≥1s 上报 `impression` | 列表页 |
| A4 | 点卡片进详情 | 详情页展示完整信息、限制条款、"即将离开平台"外链按钮；上报 `detail_view` | `/ad/:id` |
| A5 | 点"前往商家页面" | 先到平台内中间页，提示目标域名 + 离开平台；用户确认后才跳转，此时上报 `link_click` | `/go/:adId` |
| A6 | 收藏 / 隐藏 / 举报 / 调偏好 | 均以匿名标识落库，无需注册；显示轻量 toast 确认 | 详情页、列表卡片菜单、`/preferences` |
| A7 | 下次再访问 | Cookie 仍在则收藏、隐藏、偏好延续；Cookie 丢失则提示"收藏保存在本设备，清理浏览器会丢失" | `/favorites` |

> 关键点：A1–A5 全程无注册墙、无弹窗打断、无倒计时遮罩。

### 旅程 B：商家提交 → 审核 → 上线

| 步 | 角色 | 动作 | 系统行为 / 状态变化 |
| --- | --- | --- | --- |
| B1 | 商家 | 注册/登录商家账号，填商家名、联系人、手机/邮箱、所在城市、主营类别 | 商家状态 `active`；手机/邮箱需格式校验，不做短信验证（P2） |
| B2 | 商家 | 提交广告：标题、描述、一级类别 + 二级标签、城市、价格/优惠文案、有效期、落地页 URL、图片 | 前端即时校验（标题 ≤40 字、有效期 ≤90 天、URL 必须 http/https）；提交成功 → 广告状态 `pending` |
| B3 | 系统 | 自动预检：禁用词/敏感行业关键词命中、URL 黑名单/短链/非 http(s)/可执行文件后缀、图片类型与大小 | 预检不通过 → 直接 `rejected` 并给出机器原因 + 人工复核入口 |
| B4 | 管理员 | 登录后台，看审核队列（按提交时间升序），逐条看内容 + 商家历史 | 可"通过""拒绝""编辑后通过" |
| B5 | 管理员 | 通过 | 状态 `pending` → `active`（若开始时间在未来则 `scheduled`）；写 `Review` 记录（审核人、时间、结论、原因） |
| B6 | 管理员 | 拒绝 | 状态 `pending` → `rejected`，**拒绝原因必填**；商家端可见原因并可修改后重新提交 → 回到 `pending` |
| B7 | 用户 | 看到已上线广告 | 列表/详情可见，带广告标识、商家名、有效期 |
| B8 | 系统 | 到达 `valid_to` | 状态 → `expired`，列表与详情不再公开，详情页返回"该广告已结束"页 |
| B9 | 商家 | 看效果报告 | 展示量、详情查看量、外链点击量、点击率、有效期、审核状态 |

### 旅程 C：举报 → 处置 → 反馈

| 步 | 角色 | 动作 | 系统行为 / 状态变化 |
| --- | --- | --- | --- |
| C1 | 用户 | 在详情页/卡片菜单点"举报"，选原因（虚假宣传 / 过期信息 / 价格不实 / 链接可疑 / 不当内容 / 其他）+ 选填说明 | 同一匿名标识对同一广告 24h 内重复举报合并为 1 条；生成举报码 `RP-XXXXXXXX` 并展示给用户 |
| C2 | 系统 | 落库 | 举报状态 `pending`；上报 `report` 事件；触发该广告进入"待核查"标记（不影响展示） |
| C3 | 管理员 | 举报列表按状态与时间排序，点开处理 | 状态 `pending` → `reviewing`（开始处理时自动置位） |
| C4 | 管理员 | 判定成立 → 下架（或要求整改）；判定不成立 → 驳回 | 成立：广告 `active` → `offline`（原因必填），举报 → `resolved`；不成立：举报 → `dismissed`，广告不变 |
| C5 | 用户 | 用举报码或同浏览器打开"我的举报"查状态 | 见 状态 + 处理时间 + 简要结论（不下发举报人信息给商家） |
| C6 | 管理员 | 同一商家 30 天内 ≥3 次举报成立 | 商家列表标记"高风险"，后台醒目提示（不自动封禁，人工决定） |

## 3. 分类体系（6 个一级类别，固定）

**规则**：每条广告**只能有 1 个一级类别**，搭配 **1–3 个二级标签**；二级标签可多选但不得跨一级类别。类别不可由商家自定义（避免脏数据），仅管理员可维护标签。

| # | 一级类别（slug） | 二级标签 | 典型商家 | 收录说明 |
| --- | --- | --- | --- | --- |
| 1 | 本地生活服务 `local-service` | 餐饮到店、家政保洁、维修安装、美容美发 | 小餐馆、家政公司、家电维修、理发店 | 必须填"服务城市"与"服务范围"；跨城无效 |
| 2 | 优惠与促销 `deals` | 限时折扣、优惠券领取、满减活动、赠品活动 | 社区团购、便利店、线上小店 | 仅收无明确商品归属的"纯促销"信息；必须填优惠条件与门槛 |
| 3 | 数码与家电 `digital` | 手机配件、电脑办公、家用电器、智能设备 | 数码配件店、小家电代理、办公设备商 | 需填品牌/型号；不收翻新机无说明的商品 |
| 4 | 家居与日用 `home` | 家具软装、厨房餐具、清洁收纳、床品家纺 | 家居店、软装工作室、日用批发 | 大件需注明配送范围 |
| 5 | 服饰与美妆 `fashion` | 服饰鞋包、护肤彩妆、配饰珠宝 | 女装店、美妆集合店、饰品店 | 化妆品需填"国产/进口备案信息或来源说明"字段（文本即可） |
| 6 | 运动户外与宠物 `sports-pet` | 运动健身、户外装备、宠物用品、宠物服务 | 健身房、户外店、宠物店/宠物医院(仅用品服务) | 宠物医疗类仅收"用品/洗护/寄养"，不收诊疗 |

> 说明：**教育培训类本版不接入**（涉及办学资质与未成年人合规，一人公司审核成本过高），列入 P1 待评估；医疗/金融/博彩/酒类/成人/政治类永久不接入。

## 4. 需求池（P0 / P1 / P2）

优先级定义：**P0 = MVP 上线门禁，缺一不可**；P1 = 试点期问内补齐；P2 = 验证付费意愿后再做。

### 4.1 P0（Must have，含页面级细化）

#### A. 广告浏览（用户端）

| 编号 | 模块 | 描述 | 验收标准（可测试） |
| --- | --- | --- | --- |
| P0-B-01 | 首页 `/` | 首屏说明 + 6 个一级类别入口 + "最新发布"广告流（12 条）+ 搜索框 | 首屏明文出现"本站内容均为商家付费推广，已标注广告"；6 个类别全部可点；类别卡显示该类当前在架条数；不出现任何注册引导弹窗 |
| P0-B-02 | 分类列表 `/c/:slug` | 顶部类别名 + 二级标签横滑筛选 + 排序选择器 + 卡片网格（桌面 3 列 / 平板 2 列 / 手机 1 列） | 进入后仅显示该一级类别的在架广告；切换二级标签 URL query 同步变化且可分享；刷新后筛选状态保持 |
| P0-B-03 | 搜索 `/search?q=` | 标题+描述+标签关键词匹配（SQLite `LIKE`，不区分大小写）；结果页复用列表组件 | 关键词命中标题或描述任一即返回；搜"洗衣机"能命中标签为"家用电器"且描述含该词的广告；无结果显示空状态与推荐类别 |
| P0-B-04 | 广告卡片 | 图片、广告角标、标题、商家名、价格/优惠文案、城市、有效期（"有效至 M月D日"/"即将结束"）、收藏按钮、更多菜单（隐藏/举报） | 卡片上"广告"角标始终可见（不随 hover 消失）；无图片时显示占位图不塌陷；标题超 2 行省略 |
| P0-B-05 | 详情页 `/ad/:id` | 图片、标题、"广告 · 由 X 提供"、价格与优惠条件、描述、限制条款、有效期、服务城市、商家信息块、外链按钮、收藏/隐藏/举报、"为什么看到这条" | 非 `active` 广告访问返回"该广告已结束/暂不可见"页并给同类推荐；限制条款为空时显示"商家未提供额外限制条款"而非空白；外链按钮旁必须有"即将离开本平台"提示 |
| P0-B-06 | 分页/加载更多 | 列表每页 24 条，"加载更多"按钮（不自动无限滚动，避免无边界信息流） | 点击追加下一页且不重复；到底部按钮变为"没有更多了" |
| P0-B-07 | 外链中间页 `/go/:adId` | 显示目标域名、完整 URL 文本、"即将离开本平台，请自行判断"、5 秒倒计时后启用"继续前往"，另有"返回详情" | 不做自动跳转；可疑链接（黑名单域名/短链/非 http(s)/可执行文件后缀）显示"该链接已被阻断"且无继续按钮 |
| P0-B-08 | 静态页 | `/policy/ads` 广告政策、`/policy/privacy` 隐私说明、`/about` 关于与联系方式、`/policy/report` 举报说明 | 4 个页面可从页脚与详情页到达；内容含运营主体、联系方式、数据保存说明、删除数据途径 |

#### B. 分类体系

| 编号 | 模块 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| P0-C-01 | 分类数据 | 6 个一级类别 + 各自二级标签按第 3 节初始化；带 `sort_order` | 数据库初始化后一级类别正好 6 条；每类二级标签 3–4 个；商家提交页只出现这 6 项 |
| P0-C-02 | 标签筛选 | 列表按二级标签筛选，支持单选，可清除 | 选中标签后结果 100% 含该标签；清除后恢复全类结果；URL 可分享复现 |
| P0-C-03 | 提交端约束 | 商家只能选 1 个一级类别 + 同类下 1–3 个二级标签 | 选 0 个或 >3 个标签时无法提交并给出提示；选跨类别标签时该标签不可选 |

#### C. 广告透明度

| 编号 | 模块 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| P0-T-01 | 广告标识 | 卡片左上角角标"广告"，实底强调色 + 白字，字号 ≥12px；详情页标题上方"广告 · 由 {商家名} 提供" | 抽查 10 条在架广告，10 条均可见标识；在 375px 窄屏下标识不被裁切 |
| P0-T-02 | 商家信息 | 详情页商家块：商家名、城市、主营类别、入驻时间、当前在架广告数 | 无空白字段，缺失项显示"未提供" |
| P0-T-03 | 有效期展示 | 卡片显示"有效至 MM-DD"，剩余 ≤2 天显示"即将结束"徽标；详情页显示起止日期 + 剩余天数 | 有效期跨年时正确显示年份；已过期广告不出现在任何列表 |
| P0-T-04 | 无伪装 | 全站禁止"赞助内容/推荐阅读/猜你喜欢"等易混淆措辞指代广告；外链按钮文案不得为"了解更多/立即抢购" | 全文检索前端文案，无上述词指代广告；外链按钮文案为"前往商家页面" |

#### D. 用户控制

| 编号 | 模块 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| P0-U-01 | 收藏 | 卡片/详情页一键收藏，`/favorites` 列表查看，可取消 | 收藏后图标即时变化并有 toast；刷新页面仍为已收藏；重复点击不产生重复记录 |
| P0-U-02 | 隐藏 | "不感兴趣"，立即从当前列表移除，后续列表不再出现该广告 | 隐藏后同会话内该广告不再出现；`/preferences` 可查看并恢复已隐藏条目 |
| P0-U-03 | 偏好设置 `/preferences` | 勾选感兴趣的一级类别（可多选，可全不选）、常看城市、已隐藏列表、清除全部偏好按钮 | 全不选时列表按"最新发布"展示不做个性化过滤；点"清除全部偏好"二次确认后偏好、隐藏、收藏一次清空并 toast 说明 |
| P0-U-04 | 举报入口 | 卡片更多菜单与详情页均有"举报"，原因单选（6 项）+ 说明（≤200 字，选填） | 提交后展示举报码；同一广告 24h 内重复提交返回已有举报码而不新建 |
| P0-U-05 | 举报进度查询 | `/report-status` 输入举报码或自动列出本设备提交的举报及状态 | 显示状态（待处理/处理中/已处理/不成立）+ 提交时间 + 结论文案；不泄露处理人信息 |
| P0-U-06 | 降噪提示 | 隐藏/举报后 toast 明确说明"已生效：该类广告将少出现在你的列表" | toast 不夸大效果，不承诺"永久屏蔽" |
| P0-U-07 | 偏好上限 | 单设备收藏 ≤200、隐藏 ≤500，达上限提示 | 达上限时按钮置灰并提示清理，不静默丢弃 |

#### E. 商家提交

| 编号 | 模块 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| P0-M-01 | 商家登录 `/merchant/login` | 邮箱/手机 + 密码；注册即入驻（`/merchant/signup`） | 未登录访问 `/merchant/*` 一律 302 到登录页；密码 bcrypt 存储 |

## 6. 关键业务规则（必须精确）

### 6.1 广告状态机

**状态集（7 个）**

| 状态 | 中文 | 用户端可见 | 说明 |
| --- | --- | --- | --- |
| `draft` | 草稿 | 否 | 商家保存未提交，或从 `pending` 撤回 |
| `pending` | 待审核 | 否 | 已提交，等待人工审核 |
| `scheduled` | 待生效 | 否 | 已审核通过但 `valid_from` 在未来 |
| `active` | 展示中 | 是 | 已审核通过且在有效期内 |
| `rejected` | 已拒绝 | 否 | 审核未通过，含必填原因 |
| `offline` | 已下架 | 否 | 管理员下架或商家被停用 |
| `expired` | 已过期 | 否 | `valid_to` 已过，系统自动置位 |

**迁移表**

| # | 起始 | 触发者 | 事件 | 结束 | 必备条件 / 副作用 |
| --- | --- | --- | --- | --- | --- |
| 1 | `draft` | 商家 | 提交审核 | `pending` | 全部必填项通过校验；写提交时间 |
| 2 | `pending` | 商家 | 撤回 | `draft` | — |
| 3 | `pending` | 管理员 | 通过 | `active` 或 `scheduled` | `valid_from<=now<valid_to` → `active`；否则 → `scheduled`。写 `Review` |
| 4 | `pending` | 系统预检 | 预检不通过 | `rejected` | 命中禁用词/危险 URL/禁投行业，原因自动写入 |
| 5 | `pending` | 管理员 | 拒绝 | `rejected` | **原因必填**；商家可改后重提 |
| 6 | `rejected` | 商家 | 修改后重新提交 | `pending` | 重新走完整校验；保留历史拒绝记录 |
| 7 | `rejected` | 商家 | 放弃 | `draft` | — |
| 8 | `scheduled` | 系统 | 到达 `valid_from` | `active` | 定时任务（每 10 分钟） |
| 9 | `active` / `scheduled` | 系统 | 到达 `valid_to` | `expired` | 定时任务（每 30 分钟）+ 查询层过滤双保险 |
| 10 | `active` / `scheduled` | 管理员 | 下架 | `offline` | **原因必填**。举报成立、商家停用、违规均走此路径 |
| 11 | `active` | 商家 | 编辑核心字段 | `pending` | 核心字段：标题、一级类别、二级标签、价格/优惠、有效期、落地页 URL、主图。立即从公开列表移除并等待重审 |
| 12 | `active` | 商家 | 编辑非核心字段 | 状态不变 | 非核心：描述错别字（本版**不豁免**，见 P0-M-05 从严处理）；仅"限制条款"可免重审 |
| 13 | `offline` | 管理员 | 允许整改重提 | `pending` | 保留原下架原因 |
| 14 | `expired` | 商家 | 续期（复制为新广告） | `pending`（新记录） | 不复用旧 id，避免历史数据错乱 |

**禁止的迁移**：`draft → active`、`rejected → active`、`expired → active`、`offline → active`（任何回线上都必须经过 `pending`）。

### 6.2 有效期与过期判定

| 规则 | 内容 |
| --- | --- |
| 存储 | `valid_from`、`valid_to` 存 UTC；商家按北京时间输入，后端按 UTC+8 解析后转 UTC |
| 结束时刻 | 商家选择"有效至 2026-11-30"视为 `2026-11-30 23:59:59.999 (UTC+8)` |
| 可见条件（唯一权威） | `status = 'active' AND valid_from <= now AND valid_to > now`。所有用户端查询必须带此条件，不依赖状态字段单点判断 |
| 过期判定 | `valid_to <= now` 即过期。定时任务将 `active/scheduled` 且已过期的记录置 `expired` |
| 上限 | 单条广告有效期 ≤90 天；不允许 `valid_from` 早于提交时间 24h 以上 |
| 即将结束 | `valid_to - now <= 48h` 时卡片显示"即将结束"徽标 |
| 到达 `valid_to` 的用户体验 | 列表不返回；直接访问详情返回 `410` 语义页面"该广告已结束" + 同类 3 条 |
| 特殊 | 未填 `valid_to` 不允许提交（商业信息必须有期限，属透明度要求） |

### 6.4 事件埋点口径

**统一字段**：`event_id`(uuid) / `event_type` / `ad_id` / `visitor_id` / `session_id` / `ts`(UTC) / `page`(home|list|search|detail|favorites) / `position`(列表序号, 可空) / `meta`(JSON, 如排序方式、筛选条件)。不含 IP 明文、不含设备指纹、不含第三方标识。

| 事件 | 触发时机（精确定义） | 去重规则 | 用途 |
| --- | --- | --- | --- |
| `impression` | 卡片在视口内可见面积 ≥50% 且持续 ≥1000ms（IntersectionObserver），每次卡片挂载最多触发 1 次 | 同一 `session_id` + `ad_id` 只计 1 次；服务端另按 `visitor_id + ad_id + 自然日(UTC+8)` 去重口径计算"独立展示"，原始事件全量保留 | 展示量、独立展示人数 |
| `detail_view` | 详情页数据成功渲染且主内容区可见 ≥1000ms | 同一 `session_id` + `ad_id` 30 分钟内只计 1 次 | 详情查看率 = detail_view UV / impression UV |
| `link_click` | 用户在 `/go/:adId` 点击"继续前往"并完成跳转 | 同一 `visitor_id` + `ad_id` 10 秒内只计 1 次；单日上限 20 次，超出记 `link_click_suppressed` 不计数 | 点击量、点击率 |
| `favorite` | 收藏成功（新增），写库成功后才上报 | `visitor_id + ad_id` 唯一；重复收藏不新增事件；取消收藏记 `unfavorite`，**不抵扣** favorite 计数 | 收藏率 |
| `report` | 举报提交成功并生成举报码 | 同一 `visitor_id + ad_id` 24h 内合并为 1 条举报、1 个事件 | 举报率、内容质量 |
| `hide` | 点击"不感兴趣"成功 | 同一 `visitor_id + ad_id` 唯一；重复点击不新增事件 | 降噪效果、负反馈率 |
| `external_blocked` | 外链被安全策略阻断 | 不去重 | 安全监控 |

**指标口径**

| 指标 | 公式 | 注意 |
| --- | --- | --- |
| 展示量 | `count(impression)` | 商家报告用此值，标注"含重复展示" |
| 独立展示 | `count(distinct visitor_id) where event=impression` | 后台内部分析用 |
| 详情查看量 | `count(detail_view)` | — |
| 点击量 | `count(link_click)` | **不得**称为"成交"或"订单" |
| 点击率 | `link_click / detail_view`（详情页点击率）与 `link_click / impression`（整体点击率）两个口径**并列展示**，必须标注分母 | 报告中禁止只写"点击率"而不写分母 |
| 收藏率 | `favorite UV / detail_view UV` | — |
| 举报率 | `report 数 / impression 数` | 以万分比展示更可读 |

**上报方式**：前端在事件成立后 `POST /api/events`（`sendBeacon` 优先，失败降级 fetch），批量 ≤20 条；服务端校验 `ad_id` 存在且事件类型在枚举内，异常事件丢弃并记日志。上报失败不阻塞用户操作。

### 6.5 匿名用户身份载体

| 项 | 规则 |
| --- | --- |
| 载体 | Cookie `adx_vid`，值 = `base64url(随机 32 字节) + "." + HMAC-SHA256(前段, server_secret)` 前 16 字节 |
| 属性 | `HttpOnly`、`SameSite=Lax`、`Path=/`、`Max-Age=15552000`（180 天）；生产环境 `Secure` |
| 采集字段 | 仅 `visitor_id`、`first_seen`、`last_seen`；无姓名、手机号、邮箱、IP 明文 |
| 关联数据 | 收藏、隐藏、偏好、举报、事件 全部以外键 `visitor_id` 关联 |
| 校验 | 签名不合法 → 丢弃并重发新标识；不报错给用户 |
| 丢失影响 | 清 Cookie/换设备视为新访客；`/favorites` 页常驻提示"收藏保存在本设备，清理浏览器或换设备将看不到" |
| 合并 | P1：注册后可把当前设备匿名数据合并到账号，合并前弹确认说明不可反向拆回 |
| 删除 | 匿名访客可在 `/preferences` 点"删除我的本站数据"，立即删除收藏/隐藏/偏好，举报保留但去标识化 |
| 风控用途 | 服务端可保留 IP 的哈希 7 天用于刷量与攻击防护，到期自动清理，并在隐私说明中披露 |

### 6.6 举报状态流转

| 状态 | 中文 | 触发 | 用户可见文案 |
| --- | --- | --- | --- |
| `pending` | 待处理 | 用户提交 | `已收到，我们会在 48 小时内处理` |
| `reviewing` | 处理中 | 管理员点"开始处理" | `正在核查该广告` |
| `resolved` | 已处理 | 管理员判定成立（下架或整改） | `经核查，该广告已被下架/整改` |
| `dismissed` | 不成立 | 管理员判定不成立 | `经核查，暂未发现违反平台规则的情况` |

**约束**：状态只进不退；`resolved`/`dismissed` 为终态，用户可在 7 天内点"仍有疑问"追加一条说明（追加不改变状态，仅通知后台）；举报码 `RP-` + 8 位大写字母数字，全局唯一且不可枚举（随机生成 + 冲突重试）；同一举报码查询不返回举报人任何信息。

### 7.1 排序

| 排序项 | 定义 | 优先级 | 默认 |
